## 这轮修实的问题

1. 六岗位正常流程需要约5次模型请求，原“每任务2次请求”会截断。现拆成每逻辑调用最多2次尝试、整个团队任务最多12次物理请求，所有角色仍共享同一个2万token任务上限
2. 模型与Jev均持久化、跨进程独占锁；目录别名归一，symlink/hardlink账本拒绝，崩溃不自动删锁或退款
3. 主+shadow Jev都记到同一本持久表。shadow等主流程结束再取独占槽，排队不提前消耗请求超时，不改变主结果
4. HTTP已dispatch后传输异常或响应体清理未确认时，Jev保留active/锁并持久停止，避免下一请求与它重叠
5. 缺usage不退款；reasoning/cache不重复加；已知错误usage先记账；错误/用户内容/密钥不进入新账本和trace

## 离线复现

解压后进入 `source/`；测试报告在 `evidence/`，根目录同时附带组合补丁。

源码根目录：`npm run check:integration`。

仅评估：`npm --prefix evaluation run check`，需要 Node.js 22+ 和 Git；不安装新依赖，不联网。插件 build/typecheck 需要已有项目依赖；官方宿主可选测试需 `DSH_NODE_MODULES` 指向已安装的官方 rc.2 node_modules。

HTTP入口：`node evaluation/transport/run.mjs` 默认只跑模拟请求。用户自行隐藏输入和最终确认的入口见 `evaluation/transport/README.zh-CN.md`，它目前只做公共合成协议/usage预检，不能当作真实任务验收。
