# 最小真实验收计划

## 已确定的范围

- 第三方源：`https://api.aiuzh.icu`；实际 external model ID：`gpt6-luna`（用户确认，尚未联网验证）
- 节约优先；项目大模型总上限 10,000,000 token，不以花完为目标
- 输入和输出所有计费 token 计入，推理若已含输出不再相加；cached input 是 input 的子集，不再次相加
- 首批 100,000 token；每任务 20,000；并发 1；每物理调用最大输出 2,048；每逻辑调用最多两次尝试，单团队任务最多12次物理模型请求
- 模型服务的自动传输重试为 0；需要修复时是显式新请求，重新预约并计费
- Jev 仅用于本项目；独立统计，首批默认防循环阈值 30 次物理调用（可配置，不是用户设置的 Jev token/费用上限），每判断最多 2 次，明确标为可重试的失败才重试
- 不发用户私有项目、历史聊天、文件路径或密钥；使用现有公开合成任务
- 用户允许必要时使用更强 GPT；当前未验证任何升级 ID，因此配置不猜 ID、不自动升级。确定具体型号及必要性后才加入显式允许清单，并仍共享本项目总账本

## 开跑前必须满足

1. 当前没有已验证可用的 API key 专用安全录入入口，不要求用户现在提交 key。用户应自行轮换聊天中出现的 key，待受控执行器审核完成后，在自己掌控的运行环境中设置新凭据，不贴回聊天。配置仅声明是否由用户完成，不存 key。本离线脚本既不读取凭据，也不能验证凭据有效。
2. 核实指定模型、接口路径、usage 字段、输入 tokenizer/全序列化开销上界、包含全部计费推理的最大输出参数；写清供应商合约证据。兼容 OpenAI 的外观不等于这些语义已相同。
3. 将唯一项目账本接入已授权的真实传输；底层 SDK 必须关闭默认重试、流式请求、隐式模型回退和不计数的“连通性测试”。所有探针、失败调用、修复和升级均入账。
4. 复用已有隔离工作区和受控独立 verifier。禁止直接在主进程执行模型生成的代码；本准备包不提供任意代码执行器。
5. 使用已接入的 openJevMeter 持久存储，主+shadow共享计数；调用前写盘，重启未决或锁未释放均阻断。禁止用新的账本路径重置批次。
6. 此前预算定义与模型 ID 已获确认，不再作为用户待答项。供应商计数语义无法证实时保持阻断。

不要为了发现 token 规则先发一个未计入预算的付费请求。必要的探针也必须满足可证明的预约上界；否则需要先通过官方说明/供应商信息完成确认。

## 执行顺序与停止条件

A. 当前已可执行的离线验收

- 运行 `npm run check`
- 测预算并发预约、各层上限、推理/缓存去重、未知 usage、错误、持久化、重启和 Jev 有界尝试
- 6 个 stage1 合成案例只验证代码分支；脚本响应没有真实模型正确率

B. 第一小批次：先协议，再最多三个独立公共任务

- 第一请求只完成最小公共任务；正确记录实际 request model、response model、usage 和已知账本差额，再决定继续
- 任务 1：简单纯函数修改，已有不可被模型改写的独立测试。成功必须有真实测试和 seal 通过
- 任务 2：公开预置失败的纯函数，第一轮独立测试失败后允许一次显式修复。记录原失败与后续真实测试，不能用“建议 retry”当作已经恢复
- 任务 3：范围/缺测试反例。要求最终保持需人工或待验证，不能因 Jev confidence 高就报告 completed
- 三项合成输入、预置代码、独立验收依据须在开始前固定并记 hash；模型输出不产生自己的唯一验收标准
- 每任务最多两轮；若实际准备不能覆盖六角色全流程，就明确称为协议/决策小样本，不声称产品端到端验收

立即停止的条件：usage 缺失/字段歧义、预算/并发无法预约、输入或输出超过供应商承诺上界、未知计费错误、模型服务错误、任何误放行、凭据/权限变动、取消、非公开数据出现。模型失败不自动重试或切换；Jev 可重试失败仍受每判断两次和批次总次数限制。

C. 小批次审阅后再扩大

只在真实检查有结果、成本记录完整、没有误放行时逐步扩大；1000 万是全项目共享上限，不应因新批次、进程重启、换模型或修复而重置。保持成本和效果证据，未满足验收依据的任务单列待验证。扩大任务类型或接管动态路由是独立变更，不由小样本通过自动授权。

## 账本行为与诚实边界

每次物理请求之前预约“最终输入上界 + 最大计费输出”。未用余额只在有效 usage 确认后释放。并发预约同步且在发送前写盘；项目、批次、任务的已用与在途预约合并核对。

任何未知 usage 保留整笔预约并永久停止当前账本；不是记录为零、扣平均值或退款。可能到达服务端的超时也一样。崩溃留下锁，未结预约重开标为未知；没有自动解锁或预算重置命令。需要对照供应商记录人工核销，不能直接删文件继续跑。

一个进程/项目只使用一个账本。跨机器分发需另一个集中式协调器，本小补丁不支持。不要复制真实账本路径为新预算继续测试。

若供应商违反上界，实际发生的 token 必须真实记录（即使已超过预算），停止后续请求；本地无法追回已经计费的 token。因此“本地不发超预算请求”依赖正确上界与服务端兑现限额，不是任何第三方都可无条件保证的硬账单封顶。

## 报告必须逐项区分

每个任务记录：公开 fixture/hash、task ID、每轮模型及实际响应版本、已知输入/总输出/推理子项、请求次数、累计 token、Jev 调用/重试/未知 usage、每轮独立验证结果、最终分支、耗时和错误类别。

- 有效完成：真实独立 verifier 与 seal 均通过 / 可判定任务。未运行或缺证据不算成功
- 失败恢复：预置/实际失败后经过显式修复且独立检查通过 / 实际进入失败恢复的任务
- 误放行：独立检查失败、越界或缺关键证据时最终仍 completed；分母只用实际存在的反例
- 无需返工却返工：独立证据已表明足够时仍不必要重复工作，须对照固定验收依据人工核查；不是统计 retry 次数就直接认定
- 额外返工：实际修复轮次/模型调用；与“无需返工却返工”分开
- 实际验证：通过/失败/未运行/待验证分开列出，不以 Jev 建议、reference label 或 replay 一致取代

小样本展示具体分子/分母和局限，不宣传生产正确率或领域总体准确率。模型意见、人工参考、独立实际测试分别记录；未运行指标为 null，不输出零失误等会让人误解已观察的数据。

金额单价未知时成本金额为 null。token 上限不等于美元/人民币金额上限。
