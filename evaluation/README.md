# Jev 预算、独立验证与 shadow 离线集成

这是冻结 0.5.4 基础上的源码候选，未安装、未发布、未改版本。默认不发网络请求、不读取环境中的凭据。父目录 stage1 与此目录现在通过真实 `JevTeamController` 接线，不再依赖另放一份参考源码。

## 离线复现

- `npm run check:integration`（源码根目录）：build、typecheck、既有测试和全部评估检查
- `npm --prefix evaluation run check`：仅 Node.js 22+，无需安装新依赖
- `npm --prefix evaluation run pilot:integrated`：四例完整组合验收

四例均使用脚本模型与脚本 Jev 回答；独立 verifier 则在临时合成项目真实运行 Node.js 测试，并进行 baseline、check、seal：

1. 固定合成修改通过独立测试和最终 seal，方可 completed
2. 实际检查退出码 1，主 Jev 高置信和 shadow 均不能改成完成
3. 检查后修改文件，最终 seal 拒绝完成
4. 五次模型与四次主/影子 Jev 全部通过 HTTP adapter 的模拟 fetch，双持久账本 + 真实独立测试 + seal 联动

合成修改是测试代码预先写死的操作，不执行任何模型输出。它验证组件联动及安全门禁，不能证明真实任务完成率、Jev准确率、省钱效果或服务端计费保证。

## 接线与预算

`src/integration.mjs` 导出 `createBudgetedTeamController`。调用方显式提供可信 verifier、单物理请求 transport、最终请求构造/计数证明、响应 decoder，以及持久账本。没有默认 fetch、隐式凭据或自动升级模型。

- 大模型所有岗位共用项目 10,000,000、首批 100,000、单团队任务 20,000 token 上限，并发 1
- 输入与全部计费输出相加；若 reasoning 已包含在输出，只计一次；缓存输入不重复相加
- 2 次是每个逻辑调用的尝试上限；一次完整团队任务最多 12 次物理模型请求，避免原“2 次总请求”误截断六角色流程
- 每请求在发送前持久预留输入有依据的上界 + 最大全部计费输出；只有可信 usage 才结算余额
- 缺 usage、传输结果不确定或超出预约，保留未决预留并停止。不会自行退款或自动重试网络请求
- 每个岗位都用同一个 task ID，不能靠换角色重置单任务预算；任务输出预算不足即停，不抬上限
- `openProjectLedger` 与 `openJevMeter` 使用独占进程锁、原子写入、fsync；目录别名归一化，账本 symlink 与 hardlink 拒绝；崩溃锁绝不自动删
- 本实现支持单机文件系统的单账本路径；不宣称跨机器或网络文件系统分布式锁
- 账本只存匿名 task/batch/call ID、计数、上限和固定错误码，不存提示词、模型输出、用户路径、请求头、key 或原始错误

Jev 不占大模型 token 总额。主+shadow 共用持久物理调用计数、失败/重试/已知token计数。30 次是这轮执行器的可配置防循环阈值，不是用户给 Jev 设的 token 或费用预算；每判断最多 2 次尝试，并发 1。调用前写入 active 标记，重启发现未决请求则阻断，不能重置计数续跑。

shadow 默认关闭。显式注入后，仍使用 stage1 有界观察器，但将物理请求延后到主流程结束，之后按单并发顺序执行；它不能抢主流程的 Jev 槽或改变主结果。主流程完成无需等待 shadow。队列等待有独立上界（主任务时限加两次 shadow 请求窗口），支持取消/卸载；取得物理执行槽后才开始最多 10 秒的请求/刷新超时，慢主流程不会提前消耗这个窗口。忽略取消的底层请求继续占槽并保留 active；不能把“观察器结束”误当成网络请求已清理。导出完整 trace/replay 时单独等待观察器。

## HTTP 模块与用户自行预检

`transport/` 已接入并经过模拟 fetch 测试。`node evaluation/transport/run.mjs` 默认离线；它不会读取密钥或发送网络请求。`transport/README.zh-CN.md` 说明用户在自己的交互终端隐藏输入并最终亲手确认的入口。该入口只做两个公共合成协议/usage请求，不运行用户项目，不替代完整真实任务验收。

任何已dispatch的HTTP传输异常（包括timeout/cancel、异常响应头或流清理未确认），Jev计数器均保留active和锁并持久停止，防止表面结束后另一请求与它重叠。本地read/cancel完成不能证明服务端停止。即使底层迟到完成，也不能自动核销未知账目。

持久化与跨进程测试在本次 Linux 云端完成；Windows 文件系统耐久语义和真实用户终端尚未实测。不支持文件/目录 fsync 或原子 rename 时，写入失败会先阻断传输，不能宣称该平台已通过真实接入验收。
