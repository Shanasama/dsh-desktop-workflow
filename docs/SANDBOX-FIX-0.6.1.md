# 0.6.1 候选：默认沙箱的跨调用验收证据

0.6.0 的自动验证器把基线写在 `os.tmpdir()`。官方 rc.2 Linux bwrap 每次 `workspace-write` 工具调用都会建立新的 `/tmp`，因此 baseline 成功后 check 和 cleanup 找不到证据。原 tgz 与失败复现保留，不覆写。

修复不改变宿主沙箱或权限。验证器在实际项目根目录创建随机 `.dsh-team-evidence-<32hex>/state.json`；宿主保存最初的 SHA-256 锚点，后续核验原样验证。该文件只含清单哈希和固定检查元数据，不含源码或凭据。目录名可能被正常 glob 列出；六岗位不能读取、搜索或修改其内容，硬链接别名也被拒绝。源文件、测试与 Git 元数据的基线保护保持启用。

仅当目录、文件、身份、链接数量、run/root 与原摘要全部验证通过，才从项目清单中排除这个确切的 state 文件。额外文件、同前缀的其它目录、状态删改或替换不能被静默忽略。清理只删除这个已确认文件及其空目录，不递归删除。

宿主在派发 baseline 前保留随机目录意图。已派发后确认丢失、输出截断或未知终态会维持项目隔离，不会因缺少已接纳 baselineRef 就宣布清理成功。明确未派发则不隔离；其它独立项目仍可运行。

只读工作区无法创建持久证据时会降为只读分析/待验证，不请求放宽权限。这是相较旧临时文件实现的明确能力边界。Windows 仍使用相同源码与既有 PowerShell 引号处理；Linux 上的真实 PowerShell 兼容测试不等同于 Windows/Electron 原生验收。

真实供应商模型与 Jev 尚未验收。官方 Web 在云桌面已安装并启动，但该环境 Chromium 阻止本地页面，未进行密钥接手。没有修改浏览器安全设置，也没有用终端普通文本任务冒充 `/team`。
