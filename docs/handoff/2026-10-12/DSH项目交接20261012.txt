2 产品目标和需要保留的行为

目标是在官方 DSH Desktop 0.2.0-rc.2 中安装一个原生插件。用户从仓库取得安装包，在设置里选择每个岗位的模型并配置 Jev，然后在原项目聊天中输入 /team 任务正文；同一聊天右侧显示团队进度、实际节点、模型与关系图。正常使用不应要求用户每轮重复填写 key、手工维护路径范围或复杂验证 profile。

六个岗位固定为 planner 规划、coordinator 协调、researcher 研究、explorer 探索、worker 执行、reviewer 审查。用户希望规划能力强、主力执行可靠，各岗位真实分工，Jev 真实参与判断、反馈、验证与升级；界面动效必须对应实际事件，不能用演示图代替运行能力。

Jev 使用 TypeSafe 的 https://api.typesafe.ai/v1/systemone 接口和上游 lane/loop-step 策略资料。插件内的 DSH adapter、JavaScript 控制逻辑和安全约束是项目自写适配，不能称为全部直接使用原作者实现，也不能称为 TypeSafe 官方 SDK。NOTICE 保留 hermes-jev-skills commit b22a21f365720cb7cf06f9b229c095176b39cdb9 的 MIT 归属；上游安装器曾检查但没有运行。

两种模型模式都要保留：
- 基础模式：六岗位使用各自已选基础模型。
- 动态路由：每岗位可另选 weak 与 strong；small lane 选该岗位 weak，medium 选基础，high/escalate 选 strong；缺候选时回退该岗位基础模型。只能使用宿主目录中实际已配置的选择。

Jev lane 属于整个运行当前所处的评估级别，不是每个 task node 各自再次分类。节点可以因为派发时间、岗位和当时 lane 不同而选择不同模型；UI 必须按 nodeId 展示实际 routing decision，不能把全局最新选择覆盖所有节点。用户只讨论过未来可能统一路由，未授权删除基础模式。

泰拉风格和原版 UI 均保留；泰拉是旧明日方舟风格的后续命名。它使用原创 CSS/SVG 的战术终端视觉，不附带游戏角色、Logo 或第三方海报。切主题不重启任务、不清空未保存设置或图谱选择。团队拓扑、任务关系图、工作流与紧凑布局继续保留。

4 运行机制与默认预算

正常流程先取得项目 baseline，再由 Jev classify 决定当前 lane。执行轮中依次规划、协调及已启用的计划审查，然后创建 kind=task 的实际任务节点，按依赖和并发限制派发。随后运行独立宿主检查，Jev step 给出 continue、retry、verify、escalate 或 complete 等决策。

continue 和 retry 常会进入新的完整规划执行轮，再次调用 planner/coordinator/计划 reviewer；不是只接着上一条工具调用执行。verify 则只再做验证，不跑新的规划执行轮。升级 lane 不重置全局时限、总派发次数、轮数或 Token 账本。不能用重建 run 来偷偷刷新预算。

完成须同时满足实际任务完成、可信独立检查通过、差异与范围可核验、保护边界通过，且最终 seal 仍有效。Jev 说 complete 只是候选决定，不能覆盖宿主硬门禁。模型自述、没有测试、全部 skip 或修改了验收基础后的新测试，都不能单独证明完成。

默认限制来自 src/team-contracts.js：
- concurrency = 2：同时运行的岗位派发上限。
- maxAgents = 12：一次运行总岗位派发预算，包含控制岗位调用，不能理解为可完成 12 个独立 task。
- maxTasks = 8：一份可执行任务计划的任务数上限。
- maxStepsPerAgent = 8：每个子代理模型请求步骤上限。
- maxDurationMs = 600000：10 分钟。
- maxRounds = 4；maxJevCalls = 10；maxRetries = 1。

STEP_LIMIT 仅允许单任务一次有界缩范围恢复，仍受原步骤、时限和全局预算约束。恢复前要检查已有部分工作，不能盲目重做。TOOL_BOUNDARY 与 PERMISSION_DENIED 不可自动重试或绕过；取消不会回滚已经写入的修改。

Token 预算默认关闭，tokenLimit = 0；启用时要求明确正整数。每次原生请求前按准确所选模型声明的完整 combined context window 预留，不用提示词粗估代替。并发请求各自需要预留；小额度可能第一步就不足。

结算依据为宿主原生 inputTokens、cacheReadTokens、cacheWriteTokens、outputTokens，reasoning 已含在 output 中。未知、残缺、中断或无法确认清理的 usage 不静默退款；开启预算时停止后续准入。physicalCalls 是准入的宿主请求尝试数，不是精确 HTTP 次数或账单数。预算不是金额保证、跨运行项目总账或跨重启持久总账。Jev 单独计次，不混入岗位 Token 额度。

Shadow Jev 只观察，独立限制超时、次数和并发，不能改变主运行决策、模型选择、权限或完成门禁。主版本别名的实际解析版本以响应为准；没有报告就显示未知。

5 工具契约与权限边界

插件业务 guard 与 DSH 原生 sandbox、审批、预设 scope 叠加。官方标准子代理继承 approval=never 和当前 sandbox；插件不自动批准、不切 full-access、不把模型选择升级解释为权限升级。

自动项目团队的常规工具能力：
- 全岗位基础读取：read、read_image、glob、grep，以及子代理回应所需的 structured_output。
- researcher 可再使用宿主实际提供的 web_search、web_fetch，仍受原生服务与权限约束。
- worker 仅在项目处于 verified 或 unverified-editable 等可编辑条件时使用 write、edit；已有文件修改应走 edit，不能 write 覆盖。
- 经过官方来源核验且当前可见的 todo_write 可用于子会话计划；不因此获得项目文件写权限。

自动项目模式不开放通用 bash/pwsh、任意代码执行、递归委派或凭据/权限修改。独立检查由受控宿主 verifier 执行。源码保留旧式无 project 的 worker 分支，不能据此声称普通 /team 自动项目模式支持任意 shell。

项目 guard 继续约束工作区外路径、符号链接、敏感凭据路径、依赖/构建目录和私有验证证据；grep 要求具体普通文件。自动识别 Node test、已安装 Jest/Vitest、TypeScript noEmit、既有 Python/Go/Rust runner 时按受控模式执行，不自动下载依赖。没有可靠项目基线时只读分析或明确受阻；缺 runner/依赖时可能保留产出但标为待验证。

candidate.2 通过官方 tools.restrict 同时缩小模型可见 schema 和原生工具查找。父级已隐藏的工具不能重新放开。DSH 原生 restrict 对 child-own 工具有保留语义，因此仍须执行 guard；structured_output 虽属于 child-own，但已在本插件 allowlist 中，不能仅凭这一点认定它是误杀根因。标准 preset 的祖先 scope 工具可被过滤，不能把所有内建工具都误当 child-own。

todo_write 身份核验组合了 host installAnchor、精确 rc.2 模块、ToolRuntime 类、官方模块 callback、ACTIVE Cordis fiber、scope、精确定义及 execute 身份。调用前和下一模型步骤前重新验证；同名伪装、卸载、换实现都不能沿用身份。rc.2 顶层 target_session 没有跨会话路由语义，官方调用仍写自己的 child session；不要自行复制一个 Todo 实现代替。

这个契约针对已核实的官方 rc.2 组合，不是隔离宿主进程内恶意插件的安全沙箱。非标准 apply、宿主升级或重复模块可能影响身份匹配，但必须有该运行证据才能确认。尚未逐项开放 skill、present、ask_user_question、jobs、workspace dependency loader 等能力，不能为追求“工具全部可用”而一次性放开。

已有审批差异必须保留在报告中：自定义嵌入宿主若审批服务返回 allowed-once，工具可能已经执行，但团队仍报告 PERMISSION_DENIED。无审批服务的 deny 测试不能证明“任何 ask 都零执行”。这不授权插件改变原生审批决定。

6 原会话反馈和图形展示

团队终态在原会话保存有界摘要，最多 6000 字符，包含目标、当前有效任务、未完成项、失败原因、关键岗位结果摘录、独立验证事实和有依据的变更清单。岗位结果是自述，宿主结构化证据才可支持验收与文件清单。摘要明确标注历史产出仅作背景，不构成新的用户指令。

通过原生 agent.inject 持久 inbox 和 sessions.flush 保存与显示，不自动唤醒主 agent、不自行发起新的模型请求。下一次用户主动发消息，宿主先建立 system head，再准入 user/message；candidate.2 修正了新会话先写 user 后建 system 导致冷读损坏的问题。

已准入摘要经过多轮、原生 resume 和冷 JSONL 重读测试，不重复、不串入其他会话。首次准入主模型前，如果用户关闭会话或显式 remove 待处理项，rc.2 都按 native canceled 处理；当前无法可靠区分两者，因此尊重取消、不强行重注入。聊天记录可能仍可查看，但不保证重新打开后自动恢复为模型输入。后续上下文压缩/裁剪由宿主控制，不承诺永久逐字保留全部摘要或原始工具日志。

candidate.3 的团队拓扑按真实节点展示任务实例、所选模型及路由原因。固定组织关系保持静态；只有新的、序列完整且 edge 校验通过的 relation_activated 才触发瞬时覆盖层。派发、依赖满足、反馈、重试、汇总含义分开；依赖满足不应误标为消息传递。Jev 决策和宿主验证分别映射。

事件按 runId + seq 消费。首载、刷新、切运行、隐藏恢复和断线恢复只建基线；重复、乱序、缺序、回退或截断不能补造历史动效。无事件的旧日志只显示静态关系。终态、过期、断连、隐藏页停止活动动效；减少动态效果模式保留静态事件含义。预览必须持续标注合成数据并禁止网络连接。
