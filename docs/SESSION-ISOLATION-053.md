# v0.5.3 会话状态与项目占用保护

运行、启动请求、命令应答、取消、历史选择及错误诊断均绑定 `sessionId` 和唯一 `runId`。两个独立项目的会话能够同时运行；同一会话只接受一个活动运行，相同请求或命令不会重复派发。原版 / 泰拉切换、内部 arknights 标识、CSS 和来源声明保留。

## 项目占用

进程级单一 current 锁改为会话索引和项目占用集合。占用在模型元数据预检之前取得，只在已跟踪子代理和验证器结束、清理确认后释放。取消过程中仍持有占用。异常清理或无法证明终态时只隔离相关项目，并显示占用会话、运行 ID、状态及脱敏阶段。

项目身份由服务器根据真实会话 cwd 确定，RPC 不能选择锁键。realpath 与 Windows 大小写统一，仓库子目录归到其仓库，链接 Git 工作树归到共用 Git 目录；非仓库目录按目录边界检查重叠。在派发前再次核对权限上下文及项目身份。宿主全局工具 guard 同时限制其它会话在已占用项目上的修改，不能靠切换会话绕过保护；只读工具保留。

跨会话修改还核验 `write/edit` 的实际目标（包括未创建的父目录和已有目标的真实路径），不以调用会话 cwd 代替目标边界；硬链接或无法核验的 cwd/目标保留保护。独立会话的 shell 必须有声明沙箱能力的执行后端，按本次 `sandbox_permissions` 或站立策略核验模式；工作区写入同时检查 workspace、平台临时目录和 `/tmp`（官方 rc.2 writableRoots 的三项边界）。任何边界与占用项目重叠或申请完全访问均阻止；范围未知的修改工具拒绝。隔离项目的原拥有者也不能继续修改。

旧 v2 占用只读取，不清除或重写。能从原会话核验项目时按该项目保护；原会话不可用、范围不明时继续保守保护并明确显示范围未确认。没有手动强制解锁或重置接口。

## 状态、历史与 UI

每个会话保留最多 8 条运行历史，历史集合保留最多 64 个可淘汰会话，活动或隔离占用不会因历史淘汰而释放。保留原有每运行输出、图节点和事件上限。请求缓存最多 256 项，未完成请求不会被优先淘汰。运行 ID 使用 UUID，跨 runtime 不会碰撞。

历史为宿主进程内存状态，在插件 runtime 重建时仍可按会话查询；完整宿主进程重启后不从磁盘恢复。没有增加包含目标或产出的额外磁盘历史文件。全局模型/岗位/凭据设置继续使用原宿主设置体系，不随会话自动改写。

runtime 和 adapter 的并发或后续 `dispose()` 返回同一清理 Promise；全部调用等待同一次预检排空、子代理/验证器结束和监听器清理，不重复执行 disposer。重复调用保留同一失败结果。清理完成前占用保持 cancelling，未知终态继续 quarantined。

侧栏组件按会话绑定；异步回复同时验证会话、请求代次和所选运行 ID。历史端点只能返回所指定会话的记录，旧请求查询返回其原运行。另一个会话的回复不能显示，也不能取消另一个运行。命令打开面板时仍检查当前挂载会话，A→B→A 的晚到回复不会打开错误面板。

## 检查失败诊断与证据边界

诊断记录使用封闭字段：阶段、固定原因分类、已知错误码、前台/后台/未知返回类型、退出码、超时/中断标志和输出流是否存在。与具体 runId 绑定并保留到其历史快照，不保存命令、stdout/stderr、原始异常文本、项目正文或凭据。UI 显示阶段、原因分类和宿主返回形状。

自动验证器清理失败不再吞掉后直接释放项目；无法确认清理时保留项目隔离。未派发的拒绝与未知已派发执行分别处理。模型/角色配置、权限和验证门禁未被放宽。

2026-10-10 的真实会话日志仅保存 team 命令及应答，没有保存截图中失败的工具原始异常。只读检查确认实际 cwd 是仓库根目录。分别以已安装 0.5.2 和候选源码，在实际目录使用隔离的官方原生服务执行 baseline：都返回前台、exit 0、analysis-only，未产生隔离锁。候选分类为 NON_FILE_INPUT；进一步只读元数据计数发现 4 个未跟踪嵌套仓库目录。没有输出其路径或正文。

这解释了真实项目自动验收降为只读分析的原因，**不能证明已定位或修复运行中宿主截图的清理锁原因**。隔离诊断未继承运行中父会话的完整 sandbox/工具组合，也未加载日常 profile。下一次经过授权的原生验收应使用新诊断明确取得失败阶段及返回分类，不能用隔离测试成功代替真实宿主验收。

> 后续更新：清理锁的机制已定位并修复。验证调用硬编码 shell 工具名 `bash`，而 Windows 宿主注册的是 `pwsh`，工具解析失败返回 `isError`，旧代码一律按“执行终态未确认”隔离项目；诊断此前只读 `result.error.code`，真实错误码位于 `result.error.info.code`，因此界面只能显示 `UNCLASSIFIED / unknown`。修复与复现证据见 [SHELL-TOOL-053.md](SHELL-TOOL-053.md)。历史遗留的毒锁仍需宿主退出重开才能清除。

## 回归

针对性回归覆盖独立项目并发、同项目/预检冲突、其它会话修改保护、取消等待清理、已结束失败的释放、子代理与检查器未知终态隔离、runtime 替换、父会话销毁、重复命令、会话历史、旧锁已知/未知范围、Windows 路径大小写/嵌套目录/共用 Git 目录、清理失败和错误脱敏、UI 晚到回复及精确历史路由。

Windows 原生验证器回归通过 24 次调用，包括两轮 baseline/check/seal/cleanup、显式验证及篡改/过期证据负例。官方 schema/ToolRuntime、Remote 注入和 adapter 契约也通过。全部服务调用使用合成传输或独立临时项目，没有模型或 Jev 调用。

本任务 Windows 原生首轮在合成项目 cleanup 观察到前台 exit 3；已保留首次失败报告，后续两次串行复核各通过 24 次调用。首次报告没有保留 runner 的解析结果，不能确定原因或宣称已修复间歇故障。测试脚本增加 verified、observation、证据文件是否存在与 stderr 是否有文本的元数据，供以后区分 runner 失败与宿主退出状态异常，不输出原始流。这也不能替代真实日常宿主截图故障的验收。当前源码针对性测试 94/94；全量 175 pass、4 fail、3 skip，改前相同环境为 170 pass、同样 4 fail、3 skip。四项失败名称一致。

全量普通测试的四项 Windows 夹具限制仍为 POSIX 安装包装脚本、bare npm/Unix cache 调用和两项 EPERM 符号链接夹具；实际 npm 离线打包与载荷审计另行核验。三项 opt-in 宿主测试未带环境变量时跳过，其官方契约已单独执行。精确测试计数及报告哈希见交付清单。

本版本为源码及待宿主验收的候选包，日常安装仍为 0.5.2。交付清单记录包审计与 SHA，不使用旧版本的 SHA256SUMS 证明候选。曾发生 exec-server 断开及恢复超时，恢复后先只读核验命令报告、进程和源码差异，再继续。没有热更、重启、结束进程、清理旧任务/锁或上传 GitHub。
