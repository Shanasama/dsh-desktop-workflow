# 0.6.3-candidate.1 云端候选说明

日期：2026-10-11。基线：保留的完整 0.6.2 云端副本。此工作区独立于冻结的 0.6.1 / 0.6.2 包；尚未推送、发布、安装到用户电脑或调用付费模型。

## 可比较的界面

- 保留泰拉 / 原版 UI、基础岗位模型与可选动态路由、团队拓扑 / 任务关系；新增工作流布局与紧凑对照。
- 任务实例按节点独立呈现；模型选择只查本节点路由记录，缺失时明确回退到启动时基础配置。不是供应商实际响应型号证明。
- 真实运行中的实例显示 1.8 秒扫描。连线只在 relation_activated 到达时播放一次 0.8 秒传递；固定岗位示意线保持静态。依赖事件表示依赖满足，不表示另一个模型已收到消息。
- 首次打开、切换运行、刷新、隐藏后恢复及断连恢复均建立基线，不重播旧关系事件；按运行 ID + seq 去重，日志缺口/截断显式提示。
- 轮询失败或超过 5 秒未更新即暂停动效，保留最后快照并提示状态未确认；终态和隐藏页面停止。系统减少动态效果时使用静态提示。
- Jev 分类/逐轮决策和宿主独立验证分别显示。Jev 建议 complete 不能替代本地完成门禁。

预览全部是合成数据。特别是“同岗位双模型”是 UI 压力情境；当前运行时仍由 Jev 给整轮确定一个 lane，再由宿主按岗位与候选配置选型，并没有在同一轮为每个节点独立判断 lane。

## 阻塞修复

STEP_LIMIT 与权限、工具边界、依赖未完成、总派发预算、时限、清理未确认等原因分别保留。未带已知来源标签的 refusal 标为 EXECUTION_REFUSED；只说明执行被拒绝、具体原因未确认，不猜成权限或模型拒绝。

只有单个执行任务的 STEP_LIMIT 可尝试一次缩小剩余工作的续做，保留部分证据并要求先检查当前状态；仍受原 maxRetries、maxStepsPerAgent、maxAgents、Token 预算及总时限约束。默认每代理 8 步和总 12 次岗位派发未提高。安全拒绝/总预算/时限不能通过这条恢复路径放宽。

只读分析、可编辑但待验证或 needsVerification 模式，也必须先完成当前执行周期才可标为 unverified；当前根任务失败及依赖受阻仍保留 blocked 和根诊断，不把零完成说成结果就绪。

本轮有效任务由 currentTaskNodeIds 标识。旧失败尝试仍留在历史，但不会永久阻断后续有效成功版本。清理未确认优先于取消，不把未确认清理显示成普通取消完成。

## 原会话反馈

使用官方 command 结果呈现启动反馈；终态使用官方 Session.append 的生产者归属来源 dsh-desktop-workflow/team-feedback，明确渲染为“多模型团队 · 运行结果”。不会调用主代理的 send/inject，也不会生成冒充主模型的 assistant 输出。

结果绑定启动时的原 Agent 和 Session 对象，每次运行只尝试一次。只输出有界的完成/未完成数量、脱敏任务标签、结构化原因及下一步，不复制目标、原始异常、原始模型输出、检查尾部或凭据。结果会进入该会话未来的主模型上下文，但自身不触发一次模型运行。

原会话已关闭或被替换时，不把结果写入同 ID 的其它会话。追加失败不盲目重试。使用官方 sessions.flush 对捕获的原 Session 执行持久化检查点。只有返回 true 才标 durable；缺后端/接口分别标 recorded，追加或检查点失败标 failed；5 秒未确认不假定成功。运行关闭会等待已启动的有界检查点。状态保留在历史快照，失败不会导致重复追加。

## 复现

npm run check:integration

设置 DSH_NODE_MODULES 为官方 rc.2 node_modules 后可运行 npm run test:production-host、npm run test:client-host、npm run test:feedback-host。这些脚本使用临时项目和惰性模型/Jev fixture；不把它们改为真实供应商调用。

直接双击随附 standalone.html 即可打开完全自包含的合成预览，不需要 Node、服务器、服务地址或密钥。HTML 的 CSP 禁止网络连接；file:// JSDOM 运行及云 Chromium 实际交互均已检查。

npm run preview:html 可重建它。

npm run preview 在本地 127.0.0.1:4173 提供合成组件预览。在当前云环境，命令执行器与云桌面浏览器网络不同，需要在云桌面 Terminal 启动预览服务。预览页不会连接宿主或 TypeSafe。
