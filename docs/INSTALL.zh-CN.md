# v0.5 安装与使用

目标宿主为官方 DSH 0.2.0-rc.2 Web Client / Desktop 使用的对应客户端接口。具体已测范围见 [验证记录](VERIFICATION.md)。

## 推荐：把安装包拖给 DSH

1. 在 GitHub 仓库 `dist/` 下载 **dsh-desktop-workflow-0.5.1.tgz**。
2. 拖到 DSH 聊天框，发送：

   > 请用官方插件管理器安装这个附件到当前 DSH 配置。不要修改我的提供方、凭据或安全权限。

3. 按 DSH 提示确认安装，必要时重新加载或重启。
4. 打开设置中的多模型团队配置。

不要用整个仓库的源码 ZIP 代替 `.tgz`。如果 DSH 不知道怎么装，可以同时给它根目录的 [INSTALL-ME.md](../INSTALL-ME.md)。

这条流程使用官方通用附件和 `plugin_manager` 工具，不是插件新增的拖拽导入器。工具需要在当前宿主中可用；例如 Creator 预设包含插件管理能力。缺工具时，不要为安装随意切换危险权限模式。

## 只配置一次

- **六岗位模型**：规划、协调、研究、探索、执行、审查。选择 DSH 已配置且可用的提供方和模型；没有模型时，先在 DSH 原生提供方设置中完成配置。
- **Jev Key**：只在设置中的专用密钥表单输入。不要发到聊天，也不要写进任务正文。
- **TypeSafe 数据许可**：阅读任务摘要、检查摘要等发送范围后，自行选择启用；保存后正常任务不重复询问。可以撤销。

密钥使用 DSH 原生本机凭据存储，界面不回读已存的明文值。rc.2 默认的本机凭据文件有用户权限保护，但不是加密保险库，也不能隔离同一操作系统用户下的所有程序。

## 开始工作

在当前项目的聊天框发送：

```text
/team 为登录表单增加输入校验，并补充测试
```

插件通过原生聊天命令启动，并自动打开当前会话右侧工作流。已保存的岗位设置会复用；项目检查由插件自动探测。配置不全或宿主不允许执行时，界面给出具体原因，不会伪装成演示或成功。

项目没有可用测试、依赖缺失或验证证据不足时，不会把这些情况当成测试通过。插件不会为了自动启动而安装依赖、扩大宿主权限或隐式购买额度。宿主的正常工具批准仍然有效。

## 切换外观

右侧工作流或团队设置的右上角，选择 **风格 → 明日方舟 / 原版 UI**。仅更改插件界面，不改变 DSH 宿主主题、模型或运行状态。选择保存在当前客户端的本地外观偏好中；没有配置凭据或同意数据发送的副作用。存储不可用时可在当前打开的插件中切换。

## 查看与停止

右侧显示团队任务、Jev 决策和验证状态。Jev 的 lane 升级不偷偷更换你选好的模型。

停止会中止本次运行并等待活动任务清理，**不会回滚已经产生的修改**。未确认清理完成的任务会阻止新运行，避免重叠写入。

## 备用：手动安装或卸载

只在知道实际 Desktop profile 时使用。不要把测试 profile 覆盖到日常配置。

```bash
dsh plugin --profile YOUR_DESKTOP_PROFILE add /absolute/path/dsh-desktop-workflow-0.5.1.tgz --ignore-scripts
```

Windows 使用安装包对应的绝对路径。卸载：

```bash
dsh plugin --profile YOUR_DESKTOP_PROFILE remove dsh-desktop-workflow --config.ignore-scripts=true
```
